# API generator

The generator reads the registries in `xml` and produces C/C++ APIs, backend conversions, and documentation. Generator development and tests are local and opt-in; they are not part of CI or the library unit-test script.

Run the commands below from the repository root in a C++ developer shell. The examples use Ninja and a single-configuration build.

## Build

```powershell
cmake -S .\generator -B .\build-generator -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build .\build-generator --target generator
```

## Usage

This standalone build needs only the generator's tinyxml2 dependency, using an installed package when available or CPM otherwise. It does not configure the graphics libraries or their dependencies. The generator can also be built through the root project with `WISDOM_BUILD_GENERATOR=ON`.

With no module names, the generator produces the Core API. Otherwise, pass module names as positional arguments; Core is loaded first to provide shared types. Input files default to the repository's `xml` directory.

```powershell
.\build-generator\generator.exe platform -wd ".\xml" -o:c ".\output\code" -o:d ".\output\docs"
```

| Option | Purpose |
|--------|---------|
| `-wd`, `--work-directory <path>` | Directory containing `wis.xml` and module XML files. |
| `-c`, `--core <path>` | Core registry file, relative to the input directory unless absolute. |
| `-o:c`, `--out:code <path>` | Code output root; defaults to the repository's `src` directory. |
| `-o:d`, `--out:doc <path>` | Documentation output root; defaults to the repository's `docs` directory. |
| `--no-docs` | Generate only code. |
| `--no-code` | Generate only documentation. |
| `-f`, `--formatter <path>` | Override the clang-format executable found at configure time. |
| `-cf`, `--clang-format-file <path>` | Select the clang-format configuration. |
| `-h`, `--help` | Display usage. |

Output options accept either a separate value or `=<path>`, for example `--out:code=generated-code`. Relative output paths are resolved from the current working directory. Missing directories are created, and each module retains its XML-defined subdirectory layout beneath the selected roots.

Code and documentation are both generated by default. A skipped output's directory is neither created nor modified, and its output path is ignored. Using `--no-code` and `--no-docs` together is an error.

```powershell
.\build-generator\generator.exe platform --no-docs -o:c ".\output\code"
.\build-generator\generator.exe platform --no-code -o:d ".\output\docs"
```

## Local tests

`WISDOM_GENERATOR_BUILD_TESTS` defaults to `OFF` and is independent of `WISDOM_BUILD_TESTS`. Enable it explicitly to build the tests in `generator\tests`; no Catch2 dependency or GPU is required.

```powershell
cmake -S .\generator -B .\build-generator -G Ninja -DCMAKE_BUILD_TYPE=Debug -DWISDOM_GENERATOR_BUILD_TESTS=ON
cmake --build .\build-generator --target generator-tests
ctest --test-dir .\build-generator -L generator --output-on-failure --no-tests=error
```

The characterization tests generate unformatted output into isolated build directories. They check the complete file set and each file's text fingerprint and length against the snapshots in `generator\tests\snapshots`. Each entry contains a stable FNV-1a 64-bit fingerprint, text character count, and relative filename. Native text streams avoid needing separate baselines for platform text-mode file I/O.

Coverage includes Core, Platform, a synthetic registry, code-only and docs-only generation, output path options, invalid arguments, and documentation updates that preserve handwritten text. Fresh and updated documentation have separate baselines; regeneration is not assumed to be identical to first-time creation. Focused table-driven tests also cover normative-word processing, including brief comments, inline comments, positive and negative phrases, word boundaries, and existing spacing behavior.

Successful tests clean up their generated output. Failed runs retain it for inspection.

### Intentional snapshot changes

Only regenerate baselines for intentional output changes. Review the snapshot diff together with the generated files before accepting it. The update target prints and retains the output directories for this review:

```powershell
cmake --build .\build-generator --target update-generator-snapshots
ctest --test-dir .\build-generator -L generator --output-on-failure --no-tests=error
```
